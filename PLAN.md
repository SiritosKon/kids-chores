## 1. Этапы серии

### Как сейчас

В `entities/streak/lib/compute.ts` веха срабатывает по условию `run % milestone.days === 0`, то
есть на 7-й, 14-й, 21-й день подряд. Поэтому бабл-чай выдался дважды. В настройках можно задать
только одно правило: `replaceMilestone` держит одну открытую веху.

### Как будет

Серия — это список этапов. Каждый этап: сколько дней подряд, награда и/или баллы. Например:

```
7 дней  → бабл-чай
15 дней → набор Лего
30 дней → 50 баллов
```

Этап срабатывает один раз за серию — в день, когда серия становится ровно такой длины. Серия
прервалась — все этапы снова доступны в новой серии.

### Модель

`streakMilestoneSchema` в `entities/settings/model/schema.ts`:

- новое поле `repeat: boolean`. Старые строки на устройствах записаны без него и работали «каждые
  N дней», поэтому в `storedSettingsSchema` отсутствующее поле читаем как `repeat: true`. Новые
  этапы пишем с `repeat: false`. Иначе пересчёт посчитал бы старый приз за 14-й день лишним и
  удалил бы его из истории.
- у открытого этапа `from`, у закрытого `to` — как сейчас. Правка этапа закрывает старую версию
  и открывает новую, выданные призы не переписываются.

Переход старых данных: при запуске (`app/model/bootstrap.ts`) открытую веху с `repeat: true`
закрываем сегодняшним днём и открываем такую же с `repeat: false`. Прошлые дни считаются по
старому правилу, призы в истории остаются, с сегодняшнего дня работает новое.

### Расчёт

- `summariseStreak` (`entities/streak/lib/compute.ts`): для `repeat: false` условие
  `run === milestone.days`, для `repeat: true` — прежнее `run % days === 0`.
- `streakProgress` (`entities/streak/lib/progress.ts`): ближайший открытый этап, у которого
  `days > current`. Если все этапы уже пройдены в текущей серии — возвращаем «все этапы пройдены»,
  без счётчика `1 / 7` на восьмой день.
- `recalculateStreaks` (`features/track-streak`) менять почти не нужно: хиты считает `compute`,
  подсчёт `celebrated` по вехам остаётся.
- `entities/settings/lib/milestones.ts`: вместо `replaceMilestone` для одного правила — функции
  на список: добавить этап, изменить этап, удалить этап. Каждая закрывает и открывает версии
  через `from`/`to`.
- Два открытых этапа с одинаковым числом дней не допускаем — проверка в форме.

### Интерфейс

- `features/streak-details` (окно серии у ребёнка): лесенка этапов — пройденные в этой серии
  с галочкой, следующий с прогрессом «ещё 3 дня до бабл-чая», дальние — серым.
- `features/celebrate-streak`: без изменений, поздравляет с каждым новым хитом.

### Тесты

`compute.test.ts`, `progress.test.ts`, `milestones.test.ts`, `recalculate.test.ts`:

- этап на 7 дней при серии 14 срабатывает один раз;
- серия прервалась и снова дошла до 7 — второй приз;
- этапы 7 и 15 в одной серии — два разных приза;
- старая веха без `repeat` читается как повторяющаяся, её прошлые призы не удаляются;
- переход при запуске: закрытие старой вехи и открытие новой.

## 2. Страница настроек

Список этапов, бонус, PIN, а дальше и награды в модалку не помещаются. Делаем полноценную
страницу с разделами.

### Навигация

Добавляем `vue-router` с hash-историей (`/#/settings`): работает на GitHub Pages без настройки
сервера, системная кнопка «Назад» и жест назад на iPad закрывают раздел. Это же заменяет
самодельный возврат «＋ Новая награда → Назад» (`reopen`/`resume` в
`features/edit-settings/model/store.ts`).

Маршруты:

```
/                     главная (pages/home)
/settings             список разделов (pages/settings)
/settings/streak      серия и этапы
/settings/bonus       бонус за все задачи дня
/settings/pin         смена PIN
```

Страница настроек доступна только в родрежиме: без активной сессии маршрут уводит на главную.
Онбординг остаётся как есть — показывается до установки PIN.

### Раскладка по слоям

- `app` — роутер и `<router-view>` вместо прямого `HomePage` в `App.vue`.
- `pages/settings` 🆕 — страница с разделами, собирает фичи ниже.
- `features/edit-settings` — из одной модалки в отдельные формы: `StreakStagesForm` (список
  этапов, «＋ Добавить этап», правка этапа, «＋ Новая награда» прямо из выбора награды),
  `BonusForm`, `PinForm`.
- `widgets/parent-menu` — пункт «Настройки» ведёт на `/settings`.
- `pages/home/model/constants.ts` — шаги знакомства с приложением ссылаются на
  `data-tour="settings-*"`; переносим их на новую страницу.

## 3. Награда с выбором

Делаем первую версию из бэклога (раздел «Детали: награда с выбором»). Вопросы «на подумать» —
статусы выдачи, подтверждение, отмена заказа — не входят.

### Что видит пользователь

1. В редакторе награды блок «Варианты»: фото, название, порядок, удаление,
   «＋ Добавить вариант» с фото из галереи или камеры. Нет вариантов — награда обычная.
2. Награда с вариантами получена любым способом — родитель выдал за баллы или пришёл приз
   серии. Сразу открывается окно выбора: крупные карточки с фото и названием, листаются
   свайпом, тап по фото — на весь экран. Выбрал → «Точно этот?» → сохранено.
3. Ребёнок закрыл окно, не выбрав — у него бейдж «🎁 Выбери подарок», тап открывает окно снова.
4. В кошельке строка «Набор Лего → Полицейский участок» с миниатюрой.

### Модель

- Новая таблица `rewardVariants: { id, rewardId, name, photo, order, createdAt, updatedAt,
  archivedAt? }`, индекс `rewardId`. Dexie `version(5)` в `shared/api/db.ts`, старые таблицы
  не трогаем.
- Фото вариантов не лежат в строке награды: список наград грузится целиком на главной, фото
  нужны только в редакторе и окне выбора.
- `spends`: опциональные `variantId`, `variantName` (снимок, как `cost`), `chosenAt`. Старые
  строки читаются как есть.
- Выданная награда с вариантами и без `variantId` — «ждёт выбора».
- Удаление варианта — в архив. После выбора в истории остаётся снимок названия, фото доступно
  по `variantId`.

### Раскладка по слоям

- `shared/lib/resizePhoto.ts` — переносим из `features/edit-child/lib`, размер и обрезку
  передаём параметром: ребёнку квадрат 256px, варианту ~1024px по длинной стороне.
- `entities/reward` — схема и репозиторий вариантов (второй репозиторий внутри слайса, не новая
  сущность и не третий вход `@x`), стор.
- `entities/spend` — поля выбора и `chooseVariant(spendId, variant)`.
- `features/edit-reward` — блок «Варианты» в `RewardEditDialog`.
- `features/choose-reward-variant` 🆕 — окно выбора и сохранение.
- `features/award-reward` и `features/celebrate-streak` — после выдачи открыть выбор, если
  у награды есть варианты.
- `widgets/goal-meter-board` — бейдж «🎁 Выбери подарок» у ребёнка с ожидающей наградой.
- `features/wallet-history` — строка с выбранным вариантом и миниатюрой.
- `features/backup` — таблица `rewardVariants` в экспорте и импорте.

### Краевые случаи

- Откат выдачи (`rollback-spend`) удаляет и выбор — он в той же строке `spends`.
- Приз серии отозван правкой истории — строка удаляется вместе с выбором.
- Вариант архивирован до выбора — пропадает из окна.
- Все варианты удалены — награда ведёт себя как обычная, ожидающие выбора строки больше не
  просят выбор.
- Экспорт с фото вариантов — проверить размер файла на 10+ вариантах.

### Тесты

Репозиторий вариантов (создание, порядок, архив), чтение старых `spends` без полей выбора,
бэкап с `rewardVariants`, определение «ждёт выбора».
