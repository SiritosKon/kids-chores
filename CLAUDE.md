# kids-chores — правила работы

PWA-трекер домашних дел для детей. Vue 3 + Quasar + Dexie (IndexedDB), деплой на GitHub Pages
из ветки `main`. Бэкенда нет: все данные живут на устройстве.

## Команды

```
npm run dev        # дев-сервер
npm run typecheck  # vue-tsc --noEmit
npm run build      # typecheck + сборка
npm run icons      # перегенерация иконок PWA
```

Перед коммитом обязателен зелёный `npm run build` — он включает проверку типов.

## Архитектура

Feature-Sliced Design. Карта слоёв и назначение слайсов — в `src/README.md`, читай его перед
тем, как добавлять файлы.

Правила, которые нельзя нарушать:

- **Импорт только вниз по слоям:** `app` → `pages` → `widgets` → `features` → `entities` → `shared`.
  Внутри слоя — нельзя.
- **Вход в слайс только через `index.ts`.** Путей вида `entities/child/model/defaults` снаружи нет.
- **Сущности не импортируют друг друга.** Исключение — явные входы `@x` (сейчас их два, оба для
  `entities/wallet`). Понадобился третий — почти наверняка логика принадлежит фиче слоем выше.
- **Новый код кладём в существующий слайс или заводим новый слайс,** а не в «общую» папку.

## Код

- **TypeScript strict.** `any`, `as any`, `@ts-ignore`, `@ts-expect-error` — нельзя. Единственное
  приведение типа в проекте живёт в `shared/api/db.ts`, там же объяснено почему.
- **Типы выводим из zod-схем** через `z.infer`, руками не дублируем. Валидация стоит только на
  границах: чтение из IndexedDB, импорт JSON, в будущем — ответы API. Внутри слоёв дальше идут
  обычные типы, без повторной проверки.
- **Схемы чтения снисходительны к старым записям.** На устройствах лежат строки, записанные
  прошлыми версиями, миграций схемы там нет. Новое обязательное поле добавляем как опциональное
  в `stored*`-схеме с подстановкой значения, иначе потеряем историю пользователя.
- **Стрелочные функции в `const`**, не `function`-декларации. Инлайновые колбэки — тоже стрелки.
- **Комментариев в коде не пишем.** Единственное исключение — `shared/api/db.ts`. Если код
  требует объяснения, переписываем код или пишем в `src/README.md`.
- **Снимки не переписываем.** `completions.points` и `spends.cost` — цена на момент события.
  Правка каталога задач или наград не должна двигать историю.
- **Строки интерфейса — на русском**, как и весь существующий UI.

## Версии

Версия одна и та же в трёх местах, менять их надо вместе:

1. `package.json` → `version` (отсюда vite подставляет `__APP_VERSION__` в шапку приложения);
2. `src/entities/app-version/model/changelog.ts` → новая запись сверху, с датой и списком
   изменений на русском;
3. текст коммита — с номером версии в скобках.

Без записи в ченджлоге пользователь увидит уведомление «Обновлено до vX», а экран «Что нового»
покажет старое.

## Планы и исследования

Планы, роадмапы и бэклоги живут **только в ветке `research`** (папки `plans/` и `research/`).
В `main` их нет и быть не должно — там только код приложения. Нужен контекст из плана — читаем
из ветки, не копируя файл в рабочую:

```
git show research:research/01-feature-backlog.md
git ls-tree -r research --name-only | grep -E '^(plans|research)/'
```

Новый план или правка существующего — коммитом в `research`, не в рабочую ветку.

## Git

- Работаем в ветке от `main`, PR в `main`. Пуш в `main` запускает деплой на Pages.
- Коммиты в стиле conventional commits, на английском: `feat:`, `fix:`, `refactor:`, `style:`,
  `chore:`, `docs:`. При подъёме версии — номер в скобках в конце заголовка.
