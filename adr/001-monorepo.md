# ADR-001. Монорепозиторий

**Статус:** заготовка — решение ещё не записано.

## О чём

Фронт, бэк и общие пакеты живут в одном репозитории. Фиксируем, почему не раздельные репозитории, как устроены пакеты и как собирается и деплоится каждая часть.

## Что отразить

- Почему монорепозиторий: общие zod-схемы API и событий без публикации пакета, одна версия и ченджлог, изменение API и клиента одним PR
- Структура: `apps/web` (нынешнее приложение), `apps/api`, `apps/notifications`, `packages/contracts`, `packages/changelog`
- npm workspaces; Turborepo — только если сборка станет медленной
- Общие правила кода для всех пакетов: TS strict, стрелочные функции, без комментариев, типы из zod
- Что собирается и куда: `web` — статика, `api` и `notifications` — Docker-образы, миграции — отдельный шаг
- Пайплайн: на PR проверяются только изменившиеся части (изменился `contracts` — все), на `main` — сборка один раз, staging, прод по контурам с подтверждением
- Порядок выкатки: миграции → `api` и `notifications` → фронт
- Переезд текущего репозитория в `apps/web`: что меняется в `deploy.yml`, `tag.yml`, `CLAUDE.md`
