# ADR-006. События и очереди

**Статус:** заготовка — решение ещё не записано.

## О чём

Событийная архитектура на Valkey с первого дня — осознанно, ради масштабирования и практики, хотя нагрузка этого не требует.

## Что отразить

- Почему брокер с первого дня и почему не Kafka
- Почему Valkey, а не Redis: бесплатно в контейнере, BSD без условий, его же дают managed-сервисы Yandex и OVH
- Streams + consumer groups: подтверждение, повторная выдача зависших, поток для необработанных
- Transactional outbox: событие пишется в одной транзакции с данными, `outbox-relay` перекладывает в Stream
- Формат события: `{ eventId, type, version, occurredAt, familyId, payload }`, схемы в `packages/contracts`
- Версии событий: новые поля добавляются, ломающее — новая `version`, какое-то время пишем обе
- Потребители защищены от повторов по `eventId`
- BullMQ для отложенных и повторяющихся задач
- Первая волна: вся цепочка (outbox → relay → Streams → `notifications`) работает сразу, потребитель пока только пишет события в лог
- Совместимость с Redis: только общая база команд 7.2, без модулей Redis 8
