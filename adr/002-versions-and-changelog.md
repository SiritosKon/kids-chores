# ADR-002. Версии, ченджлог и совместимость

**Статус:** заготовка — решение ещё не записано.

## О чём

Одна версия продукта на весь монорепозиторий и один ченджлог. Совместимость между старыми PWA на устройствах и новым сервером держат отдельные контракты.

## Что отразить

- Одна версия в корневом `package.json`, один тег `vX.Y.Z`, релиз для `X.Y.0` — как сейчас
- Правило семвера для продукта: major — ломающее для пользователя или старых клиентов, minor — фичи, patch — исправления, в том числе чисто серверные
- Общий ченджлог: `notes` для «Что нового», `internal` для GitHub Release; пустые `notes` — без уведомления «Обновлено до vX»
- `notes` на трёх языках (`ru`, `en`, `es`) — так с локализации в 0.5.x; GitHub Release — на русском
- Ченджлог в БД: таблица записей по версиям с текстами на каждом языке. Пишем запись по-прежнему в репозитории — правка проходит ревью в PR, CI проверяет, что запись для версии есть. Деплой `api` заливает записи в БД, повторная заливка той же версии перезаписывает её. Фронт берёт «Что нового» через API на своём языке и хранит последнюю копию на устройстве для работы без сети; вшитый в сборку ченджлог уходит
- HTTP API: `/v1`, внутри только добавляющие изменения, ломающее — `/v2`
- `X-App-Version` от клиента, `minClientVersion` на сервере, ответ `426` и принудительное обновление PWA
- `GET /v1/meta`: версия сервера своего контура, `minClientVersion`, коммит
- Контуры на разных версиях
- Что поменяется в правилах версий в `CLAUDE.md`
