Улучшения текущего MVP, которые делаем **на фронте + IndexedDB**, не поднимая сервер.

## Потом — к деплою EU-контура

Цель: приложение с аккаунтом работает на своём домене по HTTPS, на iPad с экрана «Домой» в
том числе. Всё, что ниже, — в той же ветке `feat/backend-0.6` или в следующих от `main` после
мержа PR #13. Решения от 28.10.2026: лимиты запросов ставим; первый запуск предлагает войти;
выход возвращает устройство к первому запуску; фото родителя и детей пока только на устройстве.
Решения от 02.11.2026: гостя нет — без входа приложением не пользуются; родитель в семье один,
приглашений нет; аккаунт создаёт Google, Face ID добавляется поверх него и включается или
выключается в настройках; страницы аккаунта и правки профиля нет — имя и фото из Google.
Решения от 03.11.2026: секретного вопроса нет; аватарка после входа по Face ID не
подтягивается — так и оставляем, ссылку на фото сервер не хранит. Решение от 04.11.2026: в
первом приближении забытый PIN сбрасывается примером для взрослых, как до аккаунта, а в
настройках PIN меняется через текущий; смена PIN через почту — позже, вместе с почтовым сервисом.
Решения от 13.11.2026: деплой по минимуму; почта — сразу: приглашение письмом, PIN кодом на почту
и вход по коду на почту; фото детей и вариантов наград — на сервере, в закрытом хранилище, без
CDN; на заставке остаётся только название.
Решения от 14.11.2026: у каждого взрослого свой PIN, и любой из них открывает родрежим на любом
устройстве семьи; Google, Telegram, почта и пароль связываются в одном аккаунте в настройках, а
тому, кто вошёл через Telegram, приложение предлагает добавить почту; есть вход по почте и паролю;
забытый PIN сбрасывается кодом на почту или повторным входом через Google или Telegram — бот
кодов не шлёт; в текстах взрослый к семье «подключается» и его «отключают», слов «выйти из семьи»
и «другая семья» нет; у приглашения одна кнопка «Принять».
Решение от 17.11.2026: секреты сервера хранятся в окружении `production` в GitHub, деплой из
Actions сам собирает из них `.env` на сервере.
Решения от 12.11.2026: в семье может быть несколько взрослых — создатель приглашает одноразовой
ссылкой или QR-кодом (писем пока не шлём), принимает запросы на вступление по почте или телефону
родителя и убирает из семьи; вход по телефону — через Telegram;
сами адреса и номера не храним, только `HMAC`; переход в нативное приложение — план в разделе
«Нативное приложение» ниже.

1. [x] **Лимиты запросов** — счётчики в Valkey до проверки сессии: 600 запросов в минуту на адрес,
   30 попыток входа за 5 минут на адрес (старт Google, passkey, dev-вход), 300 в минуту на сессию;
   ответ `429` с `Retry-After`. В ключе — HMAC адреса (IPv6 по /64) или токена, nginx передаёт
   адрес, `api` доверяет ровно одному прокси (`TRUST_PROXY_HOPS`). ADR-008, §7. Сделано 28.10.
2. [x] **Выход сбрасывает устройство** — досылаем очередь; если сети нет и есть неотправленное,
   предупреждаем, что изменения пропадут. Потом удаляем локальную базу, фото родителя и id passkey
   этого устройства и открываем первый запуск. Чужие данные на общем устройстве не остаются.
   Без сети выйти нельзя: cookie сессии скрипт не сотрёт. ADR-008, §5. Сделано 28.10.
3. [x] **Первый запуск предлагает войти** — первым шагом «Войти через Google / по Face ID» или
   «Продолжить без входа»; без входа — как сейчас: пример, PIN, знакомство. Вошёл в семью, где
   уже есть данные, — устройство берёт их, знакомство не показываем. Возврат из Google
   продолжает первый запуск с того же места. Сделано 28.10. *02.11: вход обязателен —
   «Продолжить без входа» убрано, без сервера окно предлагает повторить; последний ответ
   `/v1/me` хранится на устройстве, поэтому без сети приложение открывается; кончилась сессия —
   окно снова просит войти, данные на устройстве остаются.*
4. [x] **Хеш PIN и один PIN на семью** — PBKDF2-SHA-256, 600 000 итераций, у гостя тоже; хеш
   едет синком, новое устройство после входа PIN не спрашивает. Открытый PIN прежних версий
   переводится в хеш при первом чтении. После пяти ошибок подряд — пауза от 30 секунд до
   15 минут. Сделано 28.10.
   - [x] **Секретный вопрос** — сделан 31.10, убран 03.11: PIN меняется через почту.
   - [x] **Сброс примером для взрослых** — «Забыли PIN?» задаёт пример, после верного ответа
     устройство задаёт новый PIN и включает родрежим; в настройках PIN меняется через текущий.
     Почты на сервере нет: право Google — `openid profile`, хеша почты и SMTP нет. Сделано 04.11.
   - [x] **PIN через почту** — «Забыли PIN?» и «Забыли текущий PIN?» в настройках: родитель
     вводит почту, с которой входит, сервер сверяет её HMAC с аккаунтом и шлёт код из шести цифр.
     Код живёт 10 минут, попытка считается до сравнения, после пяти ошибок код сгорает. Без
     подтверждённой почты — пример для взрослых. В настройках PIN по-прежнему меняется через
     текущий. Сделано 13.11. *14.11: примера больше нет — без почты PIN сбрасывается повторным

     хеши всех взрослых семьи, и устройство проверяет PIN без сети. Подходит PIN любого взрослого.

     приглашения придумывает свой. Сменить PIN можно только после проверки старого на сервере

   - [x] **Сброс PIN повторным входом** — Google или Telegram, которыми аккаунт уже входил.

Пограничные случаи, которые закрывают шаги выше:

- вход Google на iPad с экрана «Домой» завершается в Safari, а сессия в приложение не попадает —
  шаг 5;
- выход оставляет на общем устройстве данные семьи и фото родителя — шаг 2;
- вход в другой аккаунт теряет неотправленные изменения прежней семьи — предупреждение, шаг 2;
- passkey отключается только для этого устройства, а id ключа живёт в `localStorage`: почистили
  сайт — ключ остаётся на сервере — список ключей в профиле, после шага 6. По коду от 04.11 ещё:
  ключ через Связку ключей один на все устройства Apple ID, поэтому выключатель на одном
  выключает вход на всех, а остальные показывают «включено»; после выхода и входа через Google
  выключатель стоит «выключено», а включить нельзя — браузер не создаёт второй ключ того же
  аккаунта; после выключения или удаления аккаунта ключ остаётся в Связке ключей мёртвым.
  Выключатель — по серверу, мёртвые ключи — через WebAuthn Signal API;
- Safari во вкладке стирает данные сайта после 7 дней без заходов — на экране «Домой» этого нет;
  вошедшему данные вернёт сервер, фото Google — следующий вход;
- фото Google не скачалось и хранится ссылкой, а ссылка умерла — аватарка откатывается на букву;
- второй родитель с другим аккаунтом получает свою семью — шаг 13: его приглашают в семью или он
  просится в неё сам;
- убранный из семьи взрослый при следующем входе получает пустую семью, но на устройстве остаётся
  PIN прежней семьи — закрыто 14.11: PIN теперь у человека, а его PIN в прежней семье больше не
  подходит;
- Pages без сервера: с обязательным входом сборка из `main` там не работает — до мержа PR #13
  решить, замораживаем ли Pages на 0.6.x (баннер переезда — патчем от `v0.6.0`) или держим PR
  до сервера, шаг 12.

## Нативное приложение

Цель: Little Big Deals в App Store и Google Play, а для России — в RuStore. Путь — Capacitor 8:
собранный `apps/web` упакован внутрь приложения, код Vue, Quasar и Dexie остаётся прежним. Tauri
— это Rust и самописные passkeys. Android TWA даёт только Android. Переписать на React Native или
Flutter — 3–5 месяцев и вторая кодовая база. Оценка — 5–7 недель работы, 8–10 недель по
календарю с проверками сторов.

1. [ ] **Аккаунты и домен** — Apple Developer ($99 в год), Google Play ($25 один раз), свой домен
   для API, passkeys и ссылок. Статус торговца в ЕС (DSA): бесплатное приложение физлица —
   «не торговец», адрес не публикуется. Личный аккаунт Play обязан провести закрытый тест:
   12 тестировщиков 14 дней подряд. Из РФ взнос Apple оплатить нечем, а проверка разработчиков
   Google не пропускает тех, кто живёт в стране под санкциями. Регистрируемся там, где живём.
2. [ ] **Оболочка** — пакет `apps/mobile` с `capacitor.config.ts` и папками `ios/`, `android/`.
   Сборка `apps/web` в режиме `native`: `base: '/'`, без service worker, без страницы «Как
   добавить на экран». Признак платформы — `shared/lib/platform`. Иконки и заставки —
   `@capacitor/assets` из нарисованных руками мастер-кадров.
3. [ ] **Сессия по токену** — в приложении адрес `capacitor://localhost` или `https://localhost`, и
   cookie сессии до API не доходит. Нативные эндпоинты входа отдают тот же токен сессии в теле
   ответа, приложение хранит его в Keychain или Keystore и шлёт в `Authorization: Bearer`.
   `SessionGuard` принимает cookie или токен; проверка `Origin` остаётся для запросов с cookie.
   CORS на `/v1` для адресов приложения.
4. [ ] **Вход в приложении** — Google во встроенном WebView запрещён: нативный вход Google
   (GoogleSignIn на iOS, Credential Manager на Android), сервер проверяет ID token, `sub` тот же,
   что в PWA. Telegram — через системный браузер и возврат в приложение по ссылке.
   **Sign in with Apple обязателен** по правилу 4.8 App Store, раз есть вход через Google: на iOS —
   нативный, на Android и в PWA — веб-поток. При удалении аккаунта Apple требует отозвать его
   токены — придётся хранить refresh token Apple. Аккаунты Google и Apple между собой не связаны:
   нужна привязка второго способа входа к аккаунту.
5. [ ] **Passkeys** — нативный плагин и файлы на домене: `/.well-known/apple-app-site-association`
   и `/.well-known/assetlinks.json`. RP ID выбираем до запуска, потом его не сменить: ключи
   перестанут работать.
6. [ ] **Push** — APNs и FCM через `@capacitor/push-notifications`, токены устройств в сервисе
   `notifications`. Для RuStore — свой плагин на Kotlin. В тексте уведомлений имён детей нет.
7. [ ] **Данные** — IndexedDB в WKWebView iOS может стереть при нехватке места: `persist()` при
   старте, синхронизация как копия. У приложения другой адрес, чем у PWA: данные семьи придут с
   сервера, а фото детей нужно перенести экспортом и импортом.
8. [ ] **Сторы** — категория Lifestyle или Productivity, не детская: в детской запрещены сторонняя
   аналитика и ссылки без проверки взрослого, а слова «для детей» в описании зарезервированы за
   ней. Возраст — анкета Apple 2026. Privacy labels и Data safety, политика конфиденциальности,
   страница удаления аккаунта для Play. Для ревью Apple — демо-аккаунт и объяснение, зачем вход
   обязателен: семья работает на нескольких устройствах.
9. [ ] **Версии и обновления** — к трём местам версии добавляются номера сборок iOS и Android.
   `X-App-Version` и `426` из шага 7 раздела выше нужны раньше: нативные версии обновляются
   медленно.
