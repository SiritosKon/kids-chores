## Потом — к деплою EU-контура

Цель: приложение с аккаунтом работает на своём домене по HTTPS, на iPad с экрана «Домой» в
том числе. Всё, что ниже, — в той же ветке `feat/backend-0.6` или в следующих от `main` после
мержа PR #13. Решения от 28.10.2026: лимиты запросов ставим; первый запуск предлагает войти;
выход возвращает устройство к первому запуску; фото родителя и детей пока только на устройстве.

1. [x] **Лимиты запросов** — счётчики в Valkey до проверки сессии: 600 запросов в минуту на адрес,
   30 попыток входа за 5 минут на адрес (старт Google, passkey, dev-вход), 300 в минуту на сессию;
   ответ `429` с `Retry-After`. В ключе — HMAC адреса (IPv6 по /64) или токена, nginx передаёт
   адрес, `api` доверяет ровно одному прокси (`TRUST_PROXY_HOPS`). ADR-008, §7. Сделано 28.10.
2. [x] **Выход сбрасывает устройство** — досылаем очередь; если сети нет и есть неотправленное,
   предупреждаем, что изменения пропадут. Потом удаляем локальную базу, фото родителя и id passkey
   этого устройства и открываем первый запуск. Чужие данные на общем устройстве не остаются.
   Без сети выйти нельзя: cookie сессии скрипт не сотрёт. ADR-008, §5. Сделано 28.10.
3. [x] **Первый запуск предлагает войти** — первым шагом «Войти через Google / по Face ID» или
   «Продолжить без входа»; без входа — как сейчас: пример, PIN, знакомство. Вошёл в семью, где
   уже есть данные, — устройство берёт их, знакомство не показываем. Возврат из Google
   продолжает первый запуск с того же места. Сделано 28.10.
4. [x] **Хеш PIN и один PIN на семью** — PBKDF2-SHA-256, 600 000 итераций, у гостя тоже; хеш
   едет синком, новое устройство после входа PIN не спрашивает. Открытый PIN прежних версий
   переводится в хеш при первом чтении. После пяти ошибок подряд — пауза от 30 секунд до
   15 минут. Сделано 28.10.
   - [ ] **«Забыли PIN?» через аккаунт** — сейчас сброс у всех через пример для взрослых. С
     аккаунтом — повторный вход тем же аккаунтом или Face ID, потом новый PIN; возврат из
     Google ведёт на сброс. Таблица ADR-008, §6.
   - [ ] **PIN не от телефона** — хеш шестизначного PIN на сервере подбирается перебором: при
     утечке базы PIN станет известен, а родители часто берут код от телефона. В окне PIN
     подсказать, что код телефона брать не надо.
5. [ ] **iPad и iOS** — HTTPS-туннель с постоянным адресом (именованный туннель Cloudflare или
   статический домен ngrok), клиент Google с этим адресом. Проверяем на iPad с экрана «Домой»:
   возвращается ли вход Google в приложение с сессией, работает ли passkey, в том числе
   созданный на iPhone или Mac и приехавший через iCloud. По результату выбираем вход для
   iPad: как сейчас, передача входа без ввода кода (приложение ждёт, пока вход завершится в
   Safari) или кодом из шести цифр. ADR-008, §3–4.
6. [ ] **Удаление аккаунта и семьи** — `DELETE /v1/me` и `DELETE /v1/family` в родрежиме, с
   подтверждением; после удаления устройство сбрасывается, как при выходе. ADR-009, §6.
7. [ ] **Версия клиента** — `X-App-Version` в каждом запросе, `426` ниже `MIN_CLIENT_VERSION`, на
   фронте — «Обновите приложение». ADR-002, ADR-008.
8. [ ] **Логи и ошибки** — журнал nginx без IP и User-Agent (сейчас стандартный формат с ними),
   GlitchTip в контуре для `api` и PWA без тел запросов и cookie, сбор логов контура, хранение 14
   дней, внешняя проверка доступности `/v1/meta` с оповещением. ADR-009, §5.
9. [ ] **Аналитика** — без сторонних трекеров: счётчики по событиям из `outbox` на сервере
   (активные семьи, отметки, награды, входы по способам) и Umami в контуре для экранов PWA — без
   cookie и без IP. ClickHouse и сервис `analytics` — когда событий станет много.
10. [ ] **Сверка ADR с кодом** — все десять предложены; расхождения: в ADR-008 права Google
    `openid email` (стали `openid profile`), CORS между `app.` и `api.` (в контуре один адрес),
    выход без удаления базы; в ADR-009 аватарки детей из набора (решили: фото пока на
    устройстве); в ADR-002 `GET /v1/changelog` и запись ченджлога в базу при миграции — не
    сделаны. Сверить, поправить и принять.
11. [ ] **Контур на сервере** — домен, VM Hetzner, prod-compose без dev-настроек, HTTPS, фаервол
    (80, 443, SSH), секреты вне репозитория, бэкапы WAL-G с проверкой восстановления, сборка
    образов и деплой из Actions с ручным подтверждением, миграции при деплое. Новый клиент
    Google с экраном согласия в рабочем режиме, политика конфиденциальности и согласие родителя.
    Тестовый клиент Google удалить.
12. [ ] **Переезд с GitHub Pages** — данные в браузере привязаны к адресу сайта, на новом домене
    их не видно. В версии на Pages — баннер «Переезжаем» с сохранением копии, на новом домене —
    импорт копии и вход. Потом Pages переадресует на домен.

Пограничные случаи, которые закрывают шаги выше:

- вход Google на iPad с экрана «Домой» завершается в Safari, а сессия в приложение не попадает —
  шаг 5;
- выход оставляет на общем устройстве данные семьи и фото родителя — шаг 2;
- вход в другой аккаунт теряет неотправленные изменения прежней семьи — предупреждение, шаг 2;
- passkey отключается только для этого устройства, а id ключа живёт в `localStorage`: почистили
  сайт — ключ остаётся на сервере — список ключей в профиле, после шага 6;
- стёртое имя возвращается при следующем входе через Google — пустое имя хранить отдельной
  отметкой, вместе с шагом 3;
- Safari во вкладке стирает данные сайта после 7 дней без заходов — на экране «Домой» этого нет;
  вошедшему данные вернёт сервер, фото Google — следующий вход;
- фото Google не скачалось и хранится ссылкой, а ссылка умерла — аватарка откатывается на букву;
- второй родитель с другим аккаунтом получает свою семью — приглашения в семью, после деплоя.
