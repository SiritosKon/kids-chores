# 04 — Персональные данные и фото детей (+ CDN)

Расследование по ПДн: что мы обрабатываем, как классифицируется **фото ребёнка**, нужен ли CDN и как грузить фото безопасно.

> ⚠️ Это инженерная проработка, **не юридическая консультация**. Перед продом с реальными детьми — свериться с юристом/DPO.

## Что из наших данных — ПДн

| Данные | ПДн? | Комментарий |
|---|---|---|
| Имя ребёнка | Да | Прямой идентификатор. |
| Email/аккаунт родителя | Да | Идентификатор + контакт. |
| **Фото ребёнка** | Да | Изображение идентифицируемого человека = ПДн. Про «биометрию» — ниже. |
| История задач/баллов/наград | Да (в связке с ребёнком) | Данные о поведении **несовершеннолетнего** — чувствительно. |
| Устройства/логи/IP | Да | Технические ПДн. |

Ключевое: **всё это — данные несовершеннолетних**, а значит **повышенная защита** и в EU (GDPR, ст. 8 — согласие родителя),
и в РФ (152-ФЗ + режим согласия). Обрабатывать по минимуму и с явной целью.

## Фото ребёнка: ПДн или биометрия?

Частый вопрос. Коротко: **обычное фото-аватар — это ПДн, но НЕ биометрия**, пока оно не используется для
идентификации по лицу.

- **РФ (152-ФЗ):** биометрические ПДн — это данные о физиологических особенностях, **используемые для установления
  личности**. Фото-аватар, который просто показывается в UI, под это **не подпадает** (позиция Роскомнадзора).
  Как только фото прогоняется через распознавание лиц / используется для доступа — становится биометрией
  (жёсткий режим, отдельное письменное согласие, потенциально ГИС ЕБС). Нам это **не нужно** — значит не делаем.
- **EU (GDPR):** фотография — персональные данные; «особая категория» (биометрия, ст. 9) — только когда обрабатывается
  **специальными техническими средствами для уникальной идентификации**. Показ аватара ≠ биометрия. Но это изображение
  ребёнка → высокая чувствительность, нужна законная основа + **родительское согласие**.

**Вывод:** при нашем сценарии (аватар в интерфейсе) фото = **обычные ПДн ребёнка**, не биометрия. Но обращаться бережно.

## Минимизация: а нужно ли вообще грузить фото на сервер?

Самый безопасный путь — **не хранить фото на сервере вообще**:

- **Фото только на устройстве** (как в текущем MVP — в IndexedDB), синкается всё, **кроме изображений**. Тогда риск/объём
  ПДн резко падают: сервер не хранит изображения детей, нечего утекать/индексировать.
- Аватар по умолчанию — **иконки/машинки** (уже есть); фото — строго **опционально и по явному включению**.

Облачные фото нужны только если хочется, чтобы **аватар-фото подтягивался на всех устройствах**. Это уже осознанный
trade-off: удобство ↔ хранение ПДн ребёнка в облаке.

## Если всё-таки грузить фото в облако — как правильно

Не «просто CDN». Публичный CDN-URL на фото ребёнка = плохо (индексируется, расшаривается ссылкой). Правильно:

- **Приватное объектное хранилище** (S3-совместимое), бакет **не публичный**.
- Доставка через **подписанные ссылки** (signed URLs, короткий TTL) или через свой API с авторизацией — **не** постоянные публичные URL.
- **Ресайз/оптимизация** на входе (аватар маленький: 256–512px) — imgproxy / Cloudflare Images / серверный sharp.
- **Регион = регион семьи** (RU-фото → RU-хранилище, EU-фото → EU-хранилище; та же изоляция, что и данные — см. `03`).
- **Шифрование at-rest**, доступ по ролям (только участники семьи), логирование доступа.
- **Удаление по запросу** (право на забвение / отзыв согласия): удаляем и оригинал, и производные, и из кешей/CDN.

### Варианты CDN/хранилища по регионам
- **EU:** Cloudflare R2 + Cloudflare Images (приватные, signed), Scaleway Object Storage + CDN, AWS S3 + CloudFront (eu) с signed URLs.
- **RU:** Yandex Object Storage (+ CDN), VK Cloud Object Storage, Selectel S3 — с приватным доступом и временными ссылками.

> «CDN» тут — про быструю доставку **уже авторизованной** картинки, а не про публичную раздачу. Кеш CDN настраивается на
> приватный режим (по подписанным URL), иначе смысл изоляции теряется.

## Публичный CDN — когда можно, когда нет

Ответ зависит от того, **что** на CDN:

- **Неперсональные ассеты — публичный CDN идеально.** Пресет-аватарки (наши рисованные заглушки), иконки задач/наград,
  статика приложения, шрифты — это **не ПДн**, они одинаковы для всех. Их и нужно раздавать через обычный публичный CDN:
  быстро, дёшево, отлично кешируется, регион не важен.
- **Реальные фото детей — публичный CDN не годится.** Причины:
  - Стабильный публичный URL можно расшарить/проиндексировать → фото ребёнка «уходит в мир».
  - «Непубличный, но не угадать» (random-ключ) — это security-by-obscurity: ссылки утекают в логи/историю/мессенджеры.
  - Трудно гарантировать удаление (право на забвение) из-за кешей CDN.
  - Плохо стыкуется с согласием и минимизацией для несовершеннолетних.
  → Реальные фото: приватное хранилище + **signed URLs с TTL** (или раздача через свой авторизованный API), регион = регион семьи.

**Итого:** публичный CDN — для генерик-ассетов (пресеты/иконки), приватная раздача — для фото конкретного ребёнка.

## Согласие, хранение, удаление
- **Согласие родителя** на обработку данных ребёнка (и отдельно — на фото), фиксируется при онбординге; политика конфиденциальности + ToS.
- **Право на удаление**: кнопка «удалить ребёнка/данные» → полное стирание (БД + хранилище + бэкапы по регламенту).
- **Срок хранения**: не держать дольше, чем нужно; политика ретеншена.
- **Доступ**: строго участники семьи (tenant-scoped), никаких кросс-семейных чтений.

## Текущее состояние по проекту
Аватарки Тимофея и Даниила — **рисованные заглушки (стоковые иллюстрации), а не реальные фото детей**. Значит это
**не ПДн**, и держать их в публичном репо / на Pages нормально (по сути генерик-ассеты — см. «Публичный CDN» выше).
На будущее:
- Пресет-аватарки и иконки задач/наград — публичные ассеты (можно на публичный CDN).
- **Реальные фото** (если пользователь загрузит) — только приватно, **вне публичного билда/репо**, в хранилище своего региона.

## Рекомендация
1. **По умолчанию — фото локально, на сервер не грузим.** Аватар-иконки/машинки как основной вариант.
2. Облачное фото — **опциональная фича** с явным согласием: приватное хранилище в регионе, signed URLs, ресайз, удаление по запросу. Классифицируем как **обычные ПДн ребёнка** (не биометрия), пока нет распознавания лиц.
3. Пресет-аватарки/иконки — публичные ассеты (ок для публичного CDN/репо); **реальные фото — приватно, вне публичного билда**.
4. Онбординг с **родительским согласием** и политикой приватности — до сбора любых реальных ПДн.
