# Research — развитие «Домашние дела детей»

Аналитика по развитию проекта из локального MVP (одно устройство, IndexedDB, PWA на GitHub Pages)
в универсальное мультисемейное приложение с бэкендом, аккаунтами и региональной изоляцией.

Живёт в отдельной ветке `research` (в `main`/`ios` не мержится). Это проектные заметки, не код.

## TL;DR (главные выводы)

1. **Фичи.** Большая часть ближайшего бэклога (редактирование наград/детей/задач, онбординг, настройка бонуса, статистика) **делается локально, без бэка** — можно двигать прямо сейчас на текущей архитектуре, вынеся конфиг из кода в IndexedDB. Бэк нужен только для синка между устройствами, аккаунтов и уведомлений.

2. **Бэкенд.** Нагрузка **крошечная** → дробить на микросервисы по доменам не нужно. Ядро — **модульный монолит** (NestJS) + PostgreSQL + Redis + объектное хранилище. Отдельными процессами выносим только асинхрон: **Notifications — с первого дня**, **Analytics + OLAP (ClickHouse) — по триггеру** (на старте события в Postgres). Брокер/очередь — **Redis Streams / BullMQ, не Kafka**.

3. **SSO.** **Свой OIDC-слой** (managed-auth не берём — ни один не покрывает оба региона). Провайдеры по региону: EU — **Google**, RU — **Yandex ID / VK ID** (Google в РФ недоступен/нестабилен).

4. **Регионы.** RU и EU держим **двумя независимыми развёртываниями** (свои БД, домены, ключи, бэкапы — ничего общего). Это закрывает и 152-ФЗ (локализация ПДн в РФ), и GDPR. Пользователь принадлежит одному региону. Фронт (SPA) регионо-независим — просто указывает на API своего региона.

5. **ПДн/фото.** Фото ребёнка = **обычные ПДн, не биометрия** (пока не используется распознавание лиц). Безопаснее всего держать фото **локально** и не грузить на сервер; если грузить — только **приватное хранилище в регионе + signed URLs** (не публичный CDN) + родительское согласие. И **убрать фото из публичного билда** при переходе на аккаунты (сейчас аватарки лежат в публичном репо).

## Baseline (что уже есть)

Vue 3 + Quasar + Vite; стейт в IndexedDB (Dexie); PWA (кеш только на проде, локально self-destroying SW);
хостинг GitHub Pages; версионирование + «Что нового»; дети/задачи/награды — константы в коде; экспорт/импорт JSON как контракт миграции.
