## TL;DR (главные выводы)

1. **Фичи.** Большая часть ближайшего бэклога (редактирование наград/детей/задач, онбординг, настройка бонуса, статистика) **делается локально, без бэка** — можно двигать прямо сейчас на текущей архитектуре, вынеся конфиг из кода в IndexedDB. Бэк нужен только для синка между устройствами, аккаунтов и уведомлений.

2. **Бэкенд.** Нагрузка **крошечная** → микросервисы не нужны. Ядро — **модульный монолит** (NestJS) + PostgreSQL + Redis (или Valkey — по облаку региона) + объектное хранилище; доменные сущности на сервисы не дробим — при нашем размере это не нужно; то, что действительно отделяется, выделяем сразу: **Notifications — отдельный сервис с первого дня**, Analytics — по триггеру. Redis на нашей нагрузке не обязателен, но **закладываем его с первого дня** — ради масштабирования и отработки событийной архитектуры: Redis Streams с consumer groups, события через transactional outbox в Postgres, BullMQ для расписаний. **Kafka не берём.**

3. **Вход.** В RU-контуре Google и Apple исключены **законом** (ч. 10 ст. 8 149-ФЗ, штрафы по ст. 13.55 КоАП с 07.07.2026) → Яндекс ID / VK ID / телефон. В EU — Google + email-код. Яндекс и VK — OAuth2, не OIDC. Библиотека в монолите (кандидат — Better Auth, спайк), не отдельный IdP. Сессии — httpOnly-cookie, API на том же сайте.

4. **Регионы.** RU и EU — **два независимых развёртывания** (свои БД, домены, ключи, бэкапы, логи, почта). С 01.07.2025 данные граждан РФ нельзя даже первично записывать за рубежом. RU — Yandex Cloud (Redis-совместимое там — только Valkey), фронт тоже из RU-облака (GitHub и Cloudflare в РФ деградируют). EU — провайдер из ЕС (OVHcloud/Scaleway), Hetzner не обслуживает владельцев с российским адресом. Главный открытый вопрос — **владелец контуров**: от него зависят вход, домены, провайдер EU и представитель по GDPR Art. 27. Русский интерфейс делает EU-контур «направленным на РФ» — для EU нужен английский.

5. **ПДн/фото.** Фото ребёнка = **обычные ПДн, не биометрия** (пока не используется распознавание лиц). Безопаснее всего держать фото **локально** и не грузить на сервер; если грузить — только **приватное хранилище в регионе + signed URLs** (не публичный CDN) + родительское согласие. И **убрать фото из публичного билда** при переходе на аккаунты (сейчас аватарки лежат в публичном репо).
